# Assignment Task(s)

**Objective**: Gain hands-on experience in deploying and configuring modern **Identity and Access Management (IAM)** solutions using **OpenID Connect (OIDC)**. Students will compare an "all-in-one" solution (Keycloak) with a "protocol-only" engine (Ory Hydra).

## Task 1: Infrastructure & Provider Setup
You are required to set up two distinct OIDC environments. For each environment, you may use the built-in identity store or an external database (PostgreSQL/MariaDB) as the backing store. Using LDAP/Active Directory will be a plus (Windows Server 2025 Demo Version should be enough).

1. **Deploy Keycloak**: * Install Keycloak (via Docker or standalone).
   - Create a new **Realm**.

   - Configure a **Client** (for your web app) and at least one **User** with credentials.

2. **Deploy Ory Hydra**:
    - Install Ory Hydra (Docker Compose is recommended. You may install other Ory's product if necessary).

   - *Note*: Hydra does not manage users. You must either use the provided "5-minute tutorial" login/consent provider or point it to a simple mock identity store.

   - Register a **Client** using the Hydra CLI.

## Task 2: The Client Application
Develop a **minimalist web application** (using Laravel, Python/Flask, Go, etc.) that acts as an OIDC Relying Party (Client).

- **Requirement A**: The app must have a "Login" button that redirects the user to the OIDC Provider.

- **Requirement B**: Upon successful authentication, the app must receive and parse the **ID Token (JWT).**

- **Requirement C**: Display the user’s information (e.g., username, email) extracted from the JWT on a "Profile" page.

- **Flexibility**: You may use the same application code for both providers, simply changing the environment variables (Discovery URL, Client ID, Client Secret).

## Task 3: Comparative Analysis & Report
Submit a technical report (PDF) covering the following:

1. **Implementation Log**: Briefly describe your deployment steps, including any challenges faced with Docker, networking, or redirect URIs. Mention all issues you faced during deployment here. **Make sure to take notes along the way.**

2.  **Protocol Observation**: Use browser developer tools or a tool like jwt.io to inspect the tokens generated by both providers. Compare the claims present in a Keycloak token versus an Ory Hydra token. Try to use both one of the signing algorithms and 'none'.

3. **The "Developer's Dilemma"**: Compare the two products based on:

   - **Ease of Setup**: Which was faster to get running? Which had fewer dependencies to other system?

   - **Flexibility**: Which gives the developer of the Relying Party more control over the user UI/UX?

    - **Feature Set**: Mention built-in features like User Registrati on, MFA, and Admin Consoles.

4. **Final Recommendation**: Under what specific project requirements would you recommend a developer use **Keycloak**? When would **Ory Hydra** be the superior choice? Provide justification for your choice.

## Submission Guidelines
- **Demonstration**: A short (2-3 minute) screen recording showing a successful login flow for both providers. Put the link to your video in the report.

- **Report**: A 3–5 page technical document. **Any sign of AI-generated report will deduct your mark by 20 points.** Writing the report in Indonesia is allowed.
